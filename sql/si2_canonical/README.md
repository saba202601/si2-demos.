# SI² Canonical Master (SQL Server)

One database for the company model and the rules: **data elements, pick lists, pick-list options, synonyms for all
of them, bureau codes, where-used and the rule engine**. It is a framework: keep it simple, and let each company
and each person add what they need in minutes, with a second person approving every change.

## Install

On the computer with SQL Server (Windows sign-in, no passwords):

```
pip install pyodbc
python install_si2_canonical.py --selftest     # builds a temporary copy, runs every flow, prints PASS / FAIL, removes it
python install_si2_canonical.py --demo         # installs SI2Canonical (+ SI2_SourceDemo to try the scan)
```

The server defaults to `SABAHOME\SQLEXPRESS02` (`--server` or `SI2_MSSQL_SERVER` to change it). Re-running the installer is safe: it
refreshes the procedures and adds only seed rows that are missing. Without Python, run `00` to `03` in order in SSMS.

| File | What it does |
|---|---|
| `00_create_database.sql` | Creates `SI2Canonical` |
| `01_schema.sql` | Tables in four schemas: `canon`, `rules`, `gov`, `intake` |
| `02_procedures.sql` | Propose / decide, quick-add procedures, rule tester, database scan, views |
| `03_seed.sql` | Generated by `build_seed.py` from every SI² app (see below) |
| `04_demo_source.sql` | Optional `SI2_SourceDemo`: a small policy / claims / billing database to scan |
| `05_how_to.sql` | Examples for every everyday task |
| `collect_si2_databases.py` | Collects from RuleEngine, BureauReporting and ISOBureauReporting and proposes what is missing |

## What is inside

| Table | Holds |
|---|---|
| `canon.SubjectArea` | 20 subject areas (Policy, Party, Vehicle, Claim, Workers Comp, Billing, Reinsurance ...) |
| `canon.DataElement` | 247 elements: business description, type, pick list, PII, bureau-reported, risk class, owner |
| `canon.PickList` / `canon.PickListOption` | 179 pick lists and 1,092 options: ISO, NCCI / WCIO, USPS states and SI² domain lists |
| `canon.Synonym` | 860+ synonyms for elements, pick lists and options: Guidewire, Duck Creek, legacy, ISO and NCCI names, abbreviations |
| `canon.BureauCodeMap` | 788 option → ISO / NCCI code mappings |
| `canon.ElementUsage` | Where-used across the SI² apps |
| `canon.ExtensionAttribute` | Any extra attribute on any object, without changing a table |
| `rules.RuleSet` / `BusinessRule` / `RuleCondition` / `RuleTestCase` | 6 rule sets, 82 rules (ISO bureau, NCCI edits, personal auto underwriting, role authority, claims triage, data quality), 35 test cases |
| `gov.ChangeRequest` | Every proposal and decision; the person who proposes cannot approve |
| `intake.ScanRun` / `intake.Candidate` | What a scan of another database found |

Principles: **never delete** (expire with an end date; every table keeps its full history, `FOR SYSTEM_TIME ALL`),
**one model, many scopes** (`GLOBAL`, `COMPANY:<code>`, `PERSON:<id>`), **synonyms for everything**, **two people for every change**.

## Everyday use

```sql
EXEC canon.usp_ProposeElement 'ROOF_AGE_BAND', N'Roof Age Band', N'Roof age grouped for rating.', @RequestedBy = N'Saba';
EXEC canon.usp_ProposePickList 'ROOF_SHAPE', N'Roof Shape', @Options = N'GABLE=Gable;HIP=Hip;FLAT=Flat', @RequestedBy = N'Saba';
EXEC canon.usp_ProposeSynonym 'ELEMENT', 'POLICY_NUMBER', N'POLICY_REF', @Source = N'Majesco', @RequestedBy = N'Saba';
EXEC rules.usp_ProposeRule 'UW_PERSONAL_AUTO', 'R12', N'Young driver, high symbol', 'REFERRAL', 'REFER',
     @ConditionsJson = N'[["DRIVER_AGE","<","25"],["VEHICLE_SYMBOL",">=","20"]]', @RequestedBy = N'Saba';
EXEC gov.usp_DecideAll @DecidedBy = N'Reviewer';                      -- the second person
EXEC rules.usp_TestRule 'R12', N'{"DRIVER_AGE":22,"VEHICLE_SYMBOL":24}';
```

## Collect from another database

```sql
EXEC intake.usp_ScanDatabase @SourceDatabase = 'OtherDb', @SourceSystem = N'Guidewire';   -- reads only
EXEC intake.usp_ProposeMissing @ScanRunId = 1;                                             -- proposals for what is missing
EXEC gov.usp_DecideAll @DecidedBy = N'Reviewer', @ScanRunId = 1;                            -- approve (or reject) them
```

Each column is matched by approved source alias, element code, synonym, element name, common abbreviations
(`_CD`, `_DT`, `_NO`, `_AMT`, `_IND` ...) and table + column. Text columns with up to 50 distinct values are treated
as code lists: their values are matched to options, and a new column whose values all belong to an existing pick
list (Y / N → `YES_NO`) reuses it. Approvals teach the model: the next scan recognizes the same names as approved aliases.

## Collect from the databases already on the server

```
python collect_si2_databases.py --dry-run              # what is missing, written to collect_report_<time>.csv
python collect_si2_databases.py --approve-as "Saba"    # propose as 'SI2 collector', approve as the second person
```

It reads (never changes) RuleEngine, BureauReporting and ISOBureauReporting: data elements, pick lists, options,
their aliases, bureau codes and rules. Anything the master already knows (by code, name or synonym) is matched and
the source's own names and ids become synonyms (so `DE020` in a RuleEngine rule means `ROOF_AGE`); anything new is
proposed. `--scan-all` also scans every other database column by column.

## Regenerating the seed

`python sql/si2_canonical/build_seed.py` (from the repository root) rebuilds `03_seed.sql` from the ISO catalog,
the NCCI / WCIO code lists, the company-model harvest, the migration and legacy code tables, the rule engine and
the role boundaries.

## Rule engine and Rule Studio

Every business rule, for every line, product, state, company and role, in one engine with the same governance as
the canonical model. Double-click **`run_rule_engine.bat`**: it self-tests on throw-away databases, then adds the
rule engine (`06_rule_engine.sql`) and the rule library (`07_rule_library.sql`) to SI2Canonical. Re-running only adds
what is missing. Log: `rule_engine_log.txt`.

* **Where a rule applies** (`rules.RuleScope`): company, line, product, state, channel, program; empty means everywhere.
* **Overrides**: rules that share an override key compete and the most specific wins (state > product > program >
  company > line), so a Florida roof rule replaces the countrywide one in Florida only.
* **Phases** run in order: data, eligibility, referral, rating, forms, compliance, billing, routing, authority, alerts.
  The outcome is DECLINE > REFER > ACCEPT; surcharges and credits combine into a premium factor.
* **Templates** (`rules.RuleTemplate`): 18 rule shapes, each owned by a role, with the questions SI² asks.
* **Roles** (`rules.Role`) and **authority** (`rules.RoleAuthority`): 16 roles from CEO to data steward; a new limit
  closes the old one the day before.
* **Decision tables** (`rules.DecisionTable`, `rules.DecisionTableRow`): notice days, minimum premium, commission;
  the most specific row wins and `*` matches anything. Illustrative values are marked.
* **Library** (`rule_library.py` → `07_rule_library.sql`): 2 synthetic companies, 14 products, 71 rules across
  homeowners, auto, umbrella, BOP, property, GL, commercial auto, WC, cyber, pricing, compliance, billing, claims,
  SIU, distribution and executive guardrails, 149 generated test cases. Regulated values are illustrative: confirm them.
* **Engine** (`rule_engine.py`): the same condition semantics as `rules.usp_TestRule`; explains every decision;
  generates test cases; finds conflicts; measures the impact of a new rule on a synthetic book (`synthetic_book.py`).

**Rule Studio** (`app_rule_studio.py`; on the PC, the `si2_rule_studio` folder → `run_rule_studio.bat`): a person picks
their role and says what they want in plain English, e.g. *Decline homes in Georgia with a roof older than 20 years*.
SI² picks the template, reads the conditions and where it applies, notices it replaces HO-E01 in Georgia, writes the
tests and shows the impact on the synthetic book. Saba sends it for approval; Sabasi approves it; only then is it live.
With `ANTHROPIC_API_KEY` set, Claude reads the sentence first and every element and code it returns is checked
against the canonical model. Without `SI2_SQL_SERVER` the Studio runs on an in-memory copy of the library.

## Claim coverage check

Double-click **`run_claim_check.bat`**: it self-tests, adds the `cov` tables (`08_coverage.sql`) and checks every claim.
Put the company's policy forms in a `forms` folder next to it (PDF or text, the file name is the form number) and they
are read too. Log: `claim_check_log.txt`.

* **Forms** (`cov.Form`, `cov.FormSection`): each form is split into what it covers (open perils or named perils, by
  coverage), what it excludes, what an endorsement gives back (with its sublimit), limits, deductibles (including a
  hurricane percentage of Coverage A) and conditions. An exclusion excludes its subject, not the words inside its
  "unless" or "whether or not" phrases.
* **Policies** (`cov.Policy`, `cov.PolicyCoverage`, `cov.PolicyForm`): limits and deductibles by coverage, and the
  forms attached to each policy.
* **Claims** (`cov.Claim`, `cov.ClaimPayment`): SI² reads the loss description (243 loss words for 40 causes of loss,
  kept as synonyms of the canonical CAUSE_OF_LOSS options), decides COVERED / NOT COVERED / REVIEW from the attached
  forms, and compares the limit, deductible, coverage, cause and payments on the claim with the policy.
* **Alerts** (`cov.CoverageAlert`, `cov.vw_AlertInbox`): coverage questions to the claims adjuster; a limit,
  deductible, coverage or cause changed in the insured's favour to the underwriter with a copy to the claims manager;
  split payments under authority and one vendor paid on many unrelated claims by the same adjuster to the claims
  manager and SIU. The adjuster on a claim cannot close an alert about it (`cov.usp_CloseAlert`). SI² never denies a
  claim: people decide.

The forms, policies and claims loaded by `08_coverage.sql` are synthetic; the form wording is SI²'s own. In the Rule
Studio, **Claim coverage** shows the alert inbox by role and each claim with the form wording behind every decision;
**Policy forms** shows how each form was read and reads a PDF you upload.
